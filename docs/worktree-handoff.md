# 当前状态、证据与跨会话交接

新会话先读 `AGENTS.md`。在独立工作树中，接着读当前目录根部的 `HANDOFF.md`，沿卡片找到模块和验证入口。在集成工作树中，接着读[项目当前状态](status.md)和[集成任务](tasks/active.md)。

## 信息归属与生命周期

| 材料 | 唯一事实来源 | 退出当前阅读路径的条件 |
| --- | --- | --- |
| 集成状态、阻塞与下一步 | docs/status.md | 由集成者更新快照，只链接最近相关结果 |
| 集成工作树正在执行的契约 | docs/tasks/active.md | 契约及结果归入 docs/validation/<task>/ 后，该入口回到 idle |
| 产品待办 | framework-optimization-roadmap.md | 按需求与证据更新，不在状态页复制 |
| 当前行为与设计理由 | 模块文档和决策记录 | 新机制取代旧机制时合并独有理由，标明取代关系并修复引用 |
| 验收结果与历史任务 | docs/validation/<task>/ | 保留基线、验收项、结果与限制；只在相关任务中读取 |
| 并行任务的进度与交接 | 对应工作树根部的 `HANDOFF.md` | 验收结果和必要证据归档、交接得到接收后，再移除本地卡片 |
| 临时输出 | 本任务明确创建的临时路径 | 可丢弃且无复查价值时清理；忽略规则不等于删除授权 |

集成状态页建议一页以内。状态页与集成任务卡都使用 `Status`、`Task`、`Next` 字段。集成工作树空闲时为 `Status: idle`、`Task: none`。各并行任务有自己的生命周期，详见下表。

## 会话收尾

1. 对照会话基线检查改动，说明本次范围和原有未提交改动的归属。
2. 对受影响行为执行必要验证；已有结果在相关输入未变时可以复用。CI 待运行、已失败或未验证均如实保留。
3. 更新本工作树负责的卡片。完成时归档任务；未完成时记录阻塞、剩余改动和下一条可执行动作。
4. 清理本任务可确认丢弃的临时文件；必要证据先保留在版本库或可访问的工件中。不要清空未知目录。
5. 确认启动入口、任务链接和验证入口可用；提交和推送遵循用户授权。

会话可以留下明确可接续的未完成工作，但不能把它标成已完成。工作区有改动时记录归属和保留原因，不以自动 reset、删除用户文件或回滚有效工作换取“干净”。只读检查不执行任务文档中的任意命令。

## 验证结果何时失效

记录被验证版本及相关未提交输入或快照。代码、依赖、配置、环境或验收契约改变并影响原检查时，结果才需要重新验证。无关文档提交、提交时间较新或 rebase 本身不自动使结果失效；检查有效输入差异后选择受影响部分。审查意见和测试结果的适用性分别判断。

复用时保留原执行时间，并说明输入为什么仍适用。检查无法运行时记录原因，不把旧结果标成新执行结果。

## 历史保留与维护

保留能解释当前行为、支持复现或避免重犯的证据与取舍。重复内容合并到当前所有者；被完全替代的记录标为历史并修复入口。删除前确认无独有理由、兼容约束或必要引用，不能按年龄或配额清空历史。

CI 原始日志受平台保留期约束；需要长期复查的材料应保留脱敏摘要或可访问工件。日常收尾只整理本任务；跨模块陈旧材料通过独立维护任务处理，不扩大普通功能修改范围。

## 并行工作与接续

例如两个会话分别处理 EventSourcing 和 Excel。为每项任务打开独立 Git 工作树，各自在根目录执行 `git rev-parse --show-toplevel`，应得到不同路径。两个会话共用相同路径时会共享任务卡、编辑内容和暂存区，`--scope` 也无法隔离写入。

每个并行工作树一次维护一张 `HANDOFF.md`。`Task` 用仓库内唯一的任务 ID；同一项工作换会话时沿用该 ID 和工作树。以下是 Excel 工作树的起始卡样例。

```markdown
Status: in_progress
Task: T-EXCEL-CSV
Next: 运行 CsvHelperTests，记录输入、命令和失败样例。

范围：CSV 写入和相应测试。
验收：复跑已定位的样例，核对输出列顺序与换行。
```

| 本工作树的状态 | 本次交接写什么 | 接手者如何继续 |
| --- | --- | --- |
| `in_progress` | 保留 `Task` 和具体的 `Next` | 从该工作树和下一条操作继续 |
| `blocked` | 加一行 `Blocker: <具体阻塞>`，写明恢复条件 | 先检查阻塞条件 |
| `completed` | 记录验收结果，添加 `Evidence: [验收记录](docs/validation/T-EXCEL-CSV/summary.md)`，再填集成者的 `Next` | 从证据复核、集成。这一行里的路径须指向实际存在的文件 |

在任一登记的工作树运行 `python "$HOME/.agents/harness/harness.py" tasks --root .`，可只读汇总各工作树根部的卡片。并行任务只更新自己的卡片和证据；集成者在整合结果后维护 `docs/status.md` 与 `docs/tasks/active.md`。工作树收尾用 `closeout --worktree-task`，详见[命令示例](harness.md)。

根部 `/HANDOFF.md` 已加入项目的 Git 忽略规则。卡片仅保存在对应检出目录，接续时应打开原工作树。移除工作树或换机器前，先把仍需接力的上下文或已完成的验收材料转存至受保护的位置，例如 `docs/validation/<task>/`，并确认接手者能访问。按项目流程提交需要共享的材料，避免把根部卡片暂存或合入集成分支。
