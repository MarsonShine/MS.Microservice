# 当前状态、证据与跨会话交接

新会话先读 AGENTS.md、[当前状态](status.md) 和其中的活动任务，再按具体问题进入模块说明。文档中心、理论资料、历史评测与原始日志按需读取，不属于默认启动材料。

## 信息归属与生命周期

| 材料 | 唯一事实来源 | 退出当前阅读路径的条件 |
| --- | --- | --- |
| 当前任务、阻塞与下一步 | docs/status.md | 更新快照，只链接最近相关结果，不追加会话流水账 |
| 正在执行的契约 | docs/tasks/active.md | 完成后将契约及结果保存在 docs/validation/<task>/，入口回到 idle |
| 产品待办 | framework-optimization-roadmap.md | 按需求与证据更新，不在状态页复制 |
| 当前行为与设计理由 | 模块文档和决策记录 | 新机制取代旧机制时合并独有理由，标明取代关系并修复引用 |
| 验收结果与历史任务 | docs/validation/<task>/ | 保留基线、验收项、结果与限制；只在相关任务中读取 |
| 工作树未完成交接 | 工作树根 HANDOFF.md | 集成后先保存必要信息，再移除临时交接 |
| 临时输出 | 本任务明确创建的临时路径 | 可丢弃且无复查价值时清理；忽略规则不等于删除授权 |

状态页建议一页以内；长度是整理提示，不是截断重要约束的理由。当前状态与任务卡使用 Status、Task、Next 字段。空闲时为 `Status: idle`、`Task: none`；完成任务的详细契约留在对应证据目录。

## 会话收尾

1. 对照会话基线检查改动，说明本次范围和原有未提交改动的归属。
2. 对受影响行为执行必要验证；已有结果在相关输入未变时可以复用。CI 待运行、已失败或未验证均如实保留。
3. 更新任务结果与当前状态。完成时归档任务；未完成时记录阻塞、剩余改动和下一条可执行动作。
4. 清理本任务可确认丢弃的临时文件；必要证据先保留在版本库或可访问的工件中。不要清空未知目录。
5. 确认启动入口、任务链接和验证入口可用；提交和推送遵循用户授权。

会话可以留下明确可接续的未完成工作，但不能把它标成已完成。工作区有改动时记录归属和保留原因，不以自动 reset、删除用户文件或回滚有效工作换取“干净”。只读检查不执行任务文档中的任意命令。

## 验证结果何时失效

记录被验证版本及相关未提交输入或快照。代码、依赖、配置、环境或验收契约改变并影响原检查时，结果才需要重新验证。无关文档提交、提交时间较新或 rebase 本身不自动使结果失效；检查有效输入差异后选择受影响部分。审查意见和测试结果的适用性分别判断。

复用时保留原执行时间，并说明输入为什么仍适用。检查无法运行时记录原因，不把旧结果标成新执行结果。

## 历史保留与维护

保留能解释当前行为、支持复现或避免重犯的证据与取舍。重复内容合并到当前所有者；被完全替代的记录标为历史并修复入口。删除前确认无独有理由、兼容约束或必要引用，不能按年龄或配额清空历史。

CI 原始日志受平台保留期约束；需要长期复查的材料应保留脱敏摘要或可访问工件。日常收尾只整理本任务；跨模块陈旧材料通过独立维护任务处理，不扩大普通功能修改范围。

## 并行工作与恢复演练

仅集成者更新 docs/status.md；独立工作树写自己的 HANDOFF.md，避免互相覆盖。集成后迁移必要证据，再移除交接。

不依赖聊天历史，沿当前入口找到任务、适用证据和下一步。记录读取量、重复检查和误读，结构检查不代表模型能力提升。是否建立周期性自动维护应另行决定。
