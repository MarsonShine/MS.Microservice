# 多工作树与跨会话交接

适用场景：任务跨多个会话、使用 `copilot-worktrees/` 并行开发，或由不同 agent 接续同一分支。单会话完成的小改动不需要交接文件。

## 状态文件分工

| 文件 | 负责内容 | 由谁更新 |
| --- | --- | --- |
| [`docs/status.md`](status.md) | 集成状态：分支、代码基线、验证范围、阻塞、下一步 | 集成者，合并后更新 |
| 工作树根目录 `HANDOFF.md` | 单个分支或工作树的进行中交接 | 该分支的执行会话 |
| [`docs/validation/`](validation/) | 可追溯的验证证据 | 执行验证的人 |

`copilot-worktrees/` 已被 Git 忽略，工作树内的 `HANDOFF.md` 也不进入版本库；需要长期保留的证据放回 `docs/validation/` 或对应模块文档。

## 交接字段

- 分支与基线 commit；
- 已完成和未完成，附路径；
- 实际执行的验证命令、结果和未跑项；
- 阻塞；
- 下一步动作。

保持一页以内。交接不是设计文档，理由和取舍写进模块文档或决策记录。

## 工作树规则

- 一个分支只做一个 slice；不要把两个无关改动放进同一工作树。
- 不要在工作树中编辑 `docs/status.md`：多个写入者会产生冲突，合并后只保留最后一份。
- 集成者先合并 slice，再更新 `docs/status.md`，然后删除 `HANDOFF.md`。
- 合并前确认分支的验证没有缺失或过期；把命令和结果写进交接。
- 同一分支被重新 rebase 后，之前的审查结论和验证结果按过期处理，需要重跑受影响部分。

## 失效判定

- 交接文件早于分支最后一次提交：过期。
- 验证证据早于被验证的代码：过期。
- 检查无法执行：写明原因，不要把上一次通过复制成新的基线。

## 恢复检查

新会话应能读取 `docs/status.md`，打开其中引用的交接或验证证据，执行一条列出的命令后继续工作。如果需要超过三次查找才能定位状态，说明交接不完整。
