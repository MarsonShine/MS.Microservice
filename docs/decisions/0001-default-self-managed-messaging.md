# 0001：默认使用 SelfManaged 消息实现

状态：已采纳
日期：2026-10-19

## 背景

- 消息契约同时支持 SelfManaged 与 Wolverine 两种实现，默认 `Messaging:Provider=SelfManaged`。
- 两种实现不能同时接管同一事务；切换不会搬迁业务数据、待发消息或死信。
- 自定义 Inbox／Outbox 表用于保留状态、索引、人工重放和审计生命周期；Wolverine 负责传输与 Handler 调度。

## 决策

默认实现保持 SelfManaged。Wolverine 作为已验证的替换实现保留，切换必须显式选择，并使用独立的业务库和队列前缀。

## 否决方案

- 默认改用 Wolverine 内置 durable inbox/outbox：状态和重放路径不再由本仓库显式控制，与教学和审计目标不符。
- 在同一 endpoint 上同时启用两种实现：会重复消费或重复投递。
- 切换时自动迁移在途消息：缺少业务幂等与在途状态证据，不能默认执行。

## 后果

- 默认路径与业务 EF Core 事务共享 Inbox/Outbox。
- 替换实现的差异必须由 Lab 六的实验结果说明，不能只靠接口相同来推断。
- 切换 provider 是运维步骤，需要单独验证，不属于配置热切换。

## 复审条件

出现规模化运维需求、且能用真实故障与恢复数据证明框架托管更合适时，再评估默认值；不得因为“框架自带”而直接改默认。
