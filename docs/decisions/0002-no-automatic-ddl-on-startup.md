# 0002：启动时不自动执行数据库迁移

状态：已采纳
日期：2026-10-19

## 背景

- Reference Web 启动时不隐式修改数据库结构；迁移由 DatabaseMigrator 单独执行。
- DatabaseMigrator 负责导出 SQL、显式应用迁移和初始化消息拓扑，便于单独审查。
- Web 使用外部身份，不持有默认管理员或隐式初始化路径。

## 决策

数据库结构变更只能通过显式迁移执行。Web 启动不得调用自动迁移，也不得在请求路径中执行 DDL。

## 否决方案

- Web 启动调用 `Database.Migrate()`：结构变更隐式发生，难以审查、回滚和与发布步骤对齐。
- 在 Web 内执行 DDL：把高权限操作混入请求宿主，放大权限和并发风险。
- 首次启动自动建库建表：会把环境准备和发布验收混为一谈。

## 后果

- 部署和本地启动都包含显式迁移步骤；缺少该步骤时按启动错误处理。
- 迁移 SQL 可以先导出、审查，再应用。
- 结构状态与代码版本的对应关系由迁移记录和部署步骤说明，而不是由启动行为猜测。

## 复审条件

如果部署平台提供带审批的独立迁移作业，可以自动化该作业；仍不得把 DDL 移回 Web 启动路径。
