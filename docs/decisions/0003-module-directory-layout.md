# 0003：多项目模块采用目录内 docs/src/test/slnx

状态：已采纳
日期：2026-10-19

## 背景

- AI、Logging、Messaging、Persistence、Idempotency、Media 等模块各有独立测试和接入说明。
- 只打开一个模块时，代码、测试和文档不应分散在多个根目录。
- 根解决方案用于全仓库开发，模块解决方案用于日常独立打开。

## 决策

多项目模块在模块目录内组合 README、docs、src、test 和独立 `.slnx`。较小的独立组件保留在根 `src/test`，Reference 与 Lab 由 `samples` 按应用组织。

## 否决方案

- 全部平铺到根 `src/test`：模块代码、测试和说明分散，只看一个模块也要跨目录查找。
- 把所有基础设施收进单一 Infrastructure 工程：目录看似整齐，但模块边界和依赖方向不可见。
- 为统一外观拆散模块目录：会破坏独立打开和独立测试的成本优势。

## 后果

- 构建工具需要识别多个源码根；模块解决方案显式列出必要的跨模块依赖。
- 独立打开解决方案不等于没有依赖，也不意味着可以只复制一个文件夹。
- 根解决方案检查整体组合，模块解决方案检查模块及其依赖，架构测试检查共享代码不引用样例。

## 复审条件

模块数量明显减少，或现有构建工具无法稳定处理多个源码根时，重新评估目录布局；仅因“看起来统一”不构成调整理由。
