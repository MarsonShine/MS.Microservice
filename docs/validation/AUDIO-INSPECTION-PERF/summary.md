文件场景使用 `dotnet run --project benchmarks/MS.Microservice.Audio.Benchmarks -c Release -- --inspection`。已存在的 WAV 为单声道、8000 Hz、PCM16、1 秒，文件名使用大写扩展名；未知文件为 8192 个零字节。计量包含打开、检查、关闭以及返回字段的断言。创建、删除和生成输入在计量外。每个场景预热 256 次，再取 7 轮、每轮 256 次的中位数。这是同一文件的重复访问，文件系统缓存会影响结果。[文件基准](../../../benchmarks/MS.Microservice.Audio.Benchmarks/InspectionBenchmarks.cs)

省略 `--inspection` 运行内存基准。输入流预先建立，每个场景预热 10,000 次，取 5 轮、每轮 100,000 次的中位数。两种基准都计量同步调用线程的托管分配。对同一份基准构建依次使用旧、新、新、旧、旧、新 DLL，各自启动独立进程；表中为每种版本三个进程结果的中位数。WAV 内存头和密集假同步字的差值较小，重点保留这两个对照以观察快路径及最坏输入。进程峰值内存、冷文件读取和网络文件系统未测量。[内存基准](../../../benchmarks/MS.Microservice.Audio.Benchmarks/Program.cs)

## 行为和测量边界

- `dotnet test test/MS.Microservice.Audio.Tests -c Release` 最终运行通过 102 项，失败 0 项，跳过 0 项。覆盖 12 字节快路径、跨读取边界的同步字、短读、提前 EOF 后恢复位置、目录或无效文件的错误，以及 WAV／MP3 元数据与资源所有权。开发期间一轮已有静音分配断言报告 7144 B；该测试单独复跑、同一构建的全模块复跑以及最终构建均通过。静音实现未修改，这次波动的原因未定。
- 用计数流对相同两份 DLL 各传入 1024 字节，进入和退出游标均为 7。WAV 都读 12 B；ID3 从 22 B 降到 12 B；全零头从 4 次读、1050 B 降到 2 次读、1024 B。把同步字放在下标 11 和 12，两版均返回 MP3。另将同步字起点逐一放在 0～1023，两种单次读取上限（3、1024 字节）共 2048 个对照均通过结果和游标检查。
- 只有打开失败才重新按路径确认是否存在。不存在的路径仍抛出 `FileNotFoundException`，文件打开后读取或探测失败仍包装为 `InvalidOperationException`。表中仅计成功打开的文件。
- 容器大小与音频数据区长度分别校验。WAV 与 MP3 混合大小写扩展名的测试均保留原始文件字节数、采样率、声道和位深。传入的流恢复位置并保持可读，方法自己打开的文件在返回后可独占打开。

## 修复前复现的行为

| 输入和入口 | 实际结果 |
| --- | --- |
| 1.0000 秒 PCM16 单声道，44.1 kHz，默认混音或单声道转立体声输出 MP3 | 两个旧入口均读回 2.0376 秒、双声道。写入器按 PCM16 解释浮点字节。使用同一输入的编辑器对照读回 1.0710 秒、单声道 |
| 一个立体声浮点 WAV，转换目标的采样格式相同，输出路径为 `.mp3` | 66 B 输出与 WAV 输入逐字节相同 |
| PCM8 单声道 8000 Hz，输入四个 `0x80`，合并时每段追加 0.001 秒静音 | 解码前四个样本为 0，追加的八个样本为 −1 |
| 演示方法使用两份有效 PCM WAV | 已生成第一份流合并文件，随后回卷输入抛出 `ObjectDisposedException` |
