# 异构视频拼接

`VideoProcessor.ConcatenateAsync` 在现有 Media 中按顺序拼接不同分辨率、帧率、编码和音轨情况的视频。所有片段经过解码、归一化及重新编码，不假定输入适合直接拼接封装。

```csharp
var result = await new VideoProcessor().ConcatenateAsync(
    ["first.mkv", "second.mp4"], "combined.mp4", new VideoConcatenationOptions
    {
        Canvas = new(1280, 720),
        FrameRate = 30,
        MaximumInputs = 16,
        ConstantRateFactor = 23
    }, cancellationToken);
```

输出支持 MP4／MKV（H.264 + AAC）和 WebM（VP9 + Opus），质量及速度复用已有视频处理编码配置。默认最多 32 个输入，允许一个输入及重复输入；单输入仍经过相同归一化流程。默认画布取第一个视频方向校正后的像素尺寸，向上补成偶数；默认帧率取其可用平均帧率，未知时需要显式指定。输出帧率必须有限且大于 0、不超过 240。未知或非正容器时长不支持。

每段根据 FFmpeg 实际显示宽高比（包含 SAR 和方向变换）等比例缩放，设置方形像素，再在固定画布中居中补黑边。已应用的旋转矩阵在过滤图末尾删除，并验证输出旋转为零，避免播放器再次旋转。缩放的两条边分别受画布约束，不先生成超过预算的中间栅格。偶数尺寸量化可能造成少量像素比例近似。输入、输出画布及奇数补齐后的尺寸均受 `MaximumDimension`／`MaximumPixels` 约束；这些是栅格检查，不是 FFmpeg 原生内存硬配额。每个输入解码和复杂过滤图使用一个线程，输出编码沿用宿主和所选编码器行为。

每段时长按 `ceil(duration × fps) / fps` 向上归到输出帧网格，对视频、音频应用相同的目标时长，因此每段最多增加一帧的末帧停留。视频缺少尾部帧时延长最后一帧，音频不足时补静音，防止容器音轨比画面长时下一段过早开始。最终统一为恒定帧率；有损音频编码可能额外包含编码器填充。

视频与音频分别将各自第一帧时间戳归零，**不保留源文件刻意设置的音画起始偏移**。例如音轨原本晚 0.2 秒开始，此入口会将其首个有效样本移到片段起点，再补齐片段尾部。需要保留原始偏移的编辑流程应另行处理，不能将此归一化行为视为无损时间线复制。

只要任意片段有音轨，输出就包含一个 48 kHz 立体声音轨：各片段选用第一个音轨，显式转换采样率和声道，无音轨片段补有限静音；全部输入无音轨时输出也无音轨。额外音轨、字幕、章节及业务元数据不作为此入口的保留契约。

输入列表在启动前限制数量，所有路径必须与输出不同，已有目标文件／目录不会覆盖。成功编码、探测画布和校验音频归一化后才通过现有原子发布辅助方法发布文件；取消、进程错误或校验失败仅清理本次临时文件。参数走 `ArgumentList`，中文、空格及引号路径无需 shell 转义。共享视频进程超时、诊断限额及临时目录规则保持一致。

真实测试需要 `RUN_MEDIA_FFMPEG_TESTS=true`，覆盖不同分辨率／帧率／编码、静音混合、时长不一致、源起始偏移、SAR、旋转元数据、VFR、重复输入以及实际解码后的颜色和音频内容。
