# 验证洗牌的终止条件与临时分配

`ValidatedShuffle` 先随机交换，再修复留在原位的元素。原实现每轮调用返回新列表的 `Shuffle()`，却没有使用返回值：这些列表副本只产生分配。修复阶段不断随机寻找“不是原位置、且自身尚未固定”的元素；当所有值相等时，根本不存在这样的候选，循环不会结束。原实现还直接调用元素的 `Equals`，遇到 null 会抛异常。

这属于共享洗牌方法的契约问题：输入可能含重复值，但方法仍须在有限工作量内结束，并保留元素和数量。现在随机阶段使用 `Random.Shared.Shuffle(CollectionsMarshal.AsSpan(list))` 在原列表上操作；修复阶段轮换固定位置，只有一个固定位置时做一次有界扫描。比较改用 `EqualityComparer<T>.Default`，同时处理 null。没有增加反射或运行时代码生成。

## 行为与验证

值互不相等且至少有两个元素时，结果保证每个值都离开原位置。重复值可能无法全部错位，此时尽力调整并结束。公开的 `IList<T>.Shuffle()` 仍返回新列表，不修改原输入；本次只改变 `ValidatedShuffle` 的内部调用。随机排列的分布不作均匀性保证，旧算法也没有此保证。

在修改前，16 个相等值的受控用例超过 **5,000 次比较**仍未结束，由测试值对象主动终止；修改后同一用例以 **176 次比较**完成。这是一个复现用例的工作量，不代表所有输入的耗时。回归测试还穷举 2 至 7 个唯一值的排列，检查重复值、null、空列表、单元素、元素数量和公开复制式洗牌。对 8,192 个元素直接调用内部随机阶段，预热后测试要求分配低于 1 KB；旧阶段每轮至少丢弃三份列表副本。

修复后的随机结果可能与旧版本不同，调用方不应依赖具体排列。若以后需要均匀随机的错位排列，应单独定义算法及统计验证；当前方法只承诺上述位置与终止条件。
