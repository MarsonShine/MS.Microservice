# `ToArray(converter)` 只枚举一次输入

原实现先调用 `source.ToArray()` 获取长度并分配目标数组，接着再次枚举 `source` 执行转换。第一次得到的数组除了长度没有被使用。一次性序列会在第二次枚举时报错；有副作用或延迟计算的序列可能在两次枚举中返回不同的值，使结果出错。它还多分配一份完整的源数组。

现在使用 `source.Select(converter).ToArray()`，读取一个元素后立即转换，最终物化结果。公开方法签名、空参数检查和结果数组的独立性保持不变。此写法只枚举输入一次，也不需要先保存源元素；没有加入反射或动态代码生成。

## 验证与取舍

在修改前运行新增的 8 个回归用例，6 个失败：一次性序列、读取与转换的顺序以及异常后的释放行为不符合预期。修改后 8 个全部通过。对于这些测试，输入枚举次数从 2 次降为 1 次；不把这一结构变化换算为未经测量的耗时或吞吐量收益。

转换现在与读取交错执行，而原实现先读完全部输入再开始转换。依赖旧副作用顺序的调用方会看到变化；单次枚举是这个 API 对延迟序列应遵守的契约。转换或读取抛错时，已完成的转换不会回滚，枚举器会被释放。后续如果发现该路径是实际热点，可按源集合类型增加基准，再决定是否需要手写物化逻辑。
