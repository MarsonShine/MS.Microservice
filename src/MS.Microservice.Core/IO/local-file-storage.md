# 本地流保存

`LocalFileStorage` 接受宿主选择的可信目录，将输入流当前位置至末尾的内容保存为随机文件名，并返回文件名。目录在构造时解析为绝对路径；调用方流始终由调用方释放。

扩展名须为一个点加 1–9 个 ASCII 字母或数字，输出统一小写。该检查只控制文件名，不识别媒体格式；HTTP 上传的类型、大小和文件头校验由 AspNetCore 组件与宿主策略负责。

保存先写同目录下本次新建的临时文件，关闭后通过不覆盖目标的移动发布。复制失败或取消时清理该临时文件，不删除其他文件。操作期间宿主需保证目录可信且稳定；这不是面向恶意本机进程的文件系统隔离。进程被强制终止或机器断电后可能有未清理的临时文件，保留期清理由宿主负责。发布后发生取消不撤销已经完成的文件。

复制、取消或发布失败时，若暂存清理成功，保留原始异常；若清理也因 I/O 或权限失败，则抛出含原错误及清理错误的 `AggregateException`。这种情况可能留有本次暂存文件，已有目标不会被删除；调用方应检查两项错误，不能把清理失败当作唯一原因。

Lab 的 `LocalUploadStorage` 保留内容根目录约束和配置接入，调用此组件保存；应用的文件记录、权限和 HTTP 下载仍由宿主负责。

## 文件生命周期与对象存储契约

`LocalFileStorage` 实现 `IFileStorage`。`StoredFileKey.Create(extension)` 创建规范化的随机 key，调用方可以先把 key 写进自己的任务／文件记录，再调用 `WriteNewAsync(key, content)`。该方法只创建新文件；同一个 key 的并发写入只有一次能发布，不覆盖既有内容。原来的 `SaveAsync` 继续生成 key 并保存，Lab 无需更改。

`OpenReadAsync(key)` 返回由调用方释放的异步文件流，缺失抛出 `FileNotFoundException`。`GetMetadataAsync` 返回长度与 UTC 最后修改时间，缺失返回 null；元数据是查询时快照。`DeleteAsync` 对缺失文件幂等，取消不撤销已经完成的删除。已打开的本地读取流允许共享删除，删除 key 后该读取流仍可读完原内容。

所有操作只接受 32 个小写十六进制字符加小写扩展名的规范 key，拒绝路径、大小写别名、临时文件名和非 ASCII 扩展名。key 是文件定位信息，不是用户授权证明；宿主需要按所属用户和文件记录验证读写权限。存储目录需由宿主独占管理，组件不防御恶意本机进程替换目录或文件链接。

`IFileStorage` 让本地存储与可选云适配器使用相同的调用方式。它不引入云 SDK、HTTP 上传校验或数据库。远端写入因网络中断而失败时，远端是否已经接受可能无法确定；调用方持有写入前生成的 key，可查询并协调自己的记录，不能仅据异常就假定对象一定不存在。删除针对当前对象，启用版本管理的云桶需另行配置历史版本保留期。
