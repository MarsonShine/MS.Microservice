# 文件摘要与重复发现

`FileHashHelper` 以 SHA-256 流式计算文件摘要，并在调用方明确提供的文件路径中查找重复候选。不遍历目录、不维护索引，也不删除或修改文件。

```csharp
using MS.Microservice.Core.IO;

var digest = await FileHashHelper.ComputeSha256Async(filePath, cancellationToken);
var groups = await FileHashHelper.FindDuplicatesAsync(filePaths, cancellationToken);
foreach (var group in groups)
{
    Console.WriteLine($"{group.Length} bytes / {group.Sha256}");
    foreach (var path in group.Paths)
        Console.WriteLine(path);
}
```

## 输入输出契约

- 摘要为 64 位大写十六进制字符串；空文件也有有效摘要。
- 流重载从**当前位置**读至末尾，支持不可寻址流，不复位、不关闭调用方的流。文件路径重载自行打开并释放文件。
- 路径先通过 `Path.GetFullPath` 规范化，再去除重复输入。Windows 使用不区分大小写的序数比较，其他平台使用区分大小写的序数比较；该策略不探测具体挂载点的大小写设置。
- 同一路径的相对、绝对、`.` 和 `..` 表达形式合并；不解析符号链接或硬链接，不按物理文件身份合并。不同链接路径可以出现在同一组中。
- 先读取文件长度，只对长度相同且至少包含两个不同路径的组计算摘要。每组包含至少两个路径，以及相同的长度和 SHA-256。摘要匹配是重复候选判定，没有额外的逐字节二次比较。
- 输出为只读集合，路径为规范化的绝对路径；组内路径及组间第一个路径按序数排序。重复输入的大小写表达不同，在平台认为相同的情况下选择序数最小的表达，使输出不依赖输入顺序。
- 所有路径必须指向可访问且稳定的普通文件。缺失路径、目录、I/O 错误、枚举器异常或检测到文件变化时，整个操作失败，不返回部分结果。只有候选文件会打开读取；非候选文件仍验证元数据是否可读。

## 资源、取消与文件变化

文件内容由 .NET SHA-256 异步流接口处理，不把完整文件读入内存。重复发现顺序读取文件，没有额外并发或后台任务；元数据、路径和输出占用与输入路径数相关的内存。

取消令牌贯穿路径枚举、候选分组和文件读取。取消后抛出 `OperationCanceledException`，已打开的文件仍释放；调用方提供的流仍保持打开，位置停留在取消时已读到的位置。同步枚举器或不遵守取消令牌的自定义流不能被强制中断。

文件读取采用 `FileShare.Read`，并比较候选收集、摘要开始前和完成后的长度及最后修改时间，同时验证读取位置。检测到变化抛出 `IOException`。这些检查**不提供文件系统快照**：共享规则、时间戳粒度、同长度改写、路径替换及读取后再次修改都可能限制检测能力。调用方应确保处理期间文件稳定；将摘要持久化为索引或据此删除文件时，需要应用自己的版本校验、并发控制和确认规则。

现有字符串摘要与 HMAC API 保持原有行为。这里的 SHA-256 是内容摘要，不能代替带密钥的完整性认证。
