# 音频编辑的帧、增益与发布

调用和参数见[Audio README](../README.md)。`AudioEditor` 独立于旧 `AudioProcessor`，共用 NAudio／LAME 依赖；旧合并、混音和转换入口的行为不随此编辑器改变。

## 帧边界与信号处理

`AudioFileReader` 将输入解码为交错 float 样本。一帧包含每个声道的一个样本，因此读取长度、起始位置和剩余量都按声道数对齐；解码长度或返回样本数不能组成整帧时抛出 `InvalidDataException`。解码器过早结束则抛出 `EndOfStreamException`。

时间换算使用 `floor(ticks × sampleRate / ticksPerSecond)`。起点必须选中输入中的一帧，时长对齐后须非零；目标时长超过尾部时仅保留剩余帧。压缩格式的 seek 精度由解码器决定，不能据此承诺逐样本精确的 MP3 寻址。

同一帧各声道使用相同系数。样本乘积使用 double 中间值，再统一限幅至 [-1, 1]，避免大但有限的增益在 float 中先溢出。NaN 和无穷输入直接拒绝，静音增益也不绕过该检查。

淡入和淡出默认关闭，时长不得为负，量化后各自不得超过选段。淡入第一帧为零、该淡入最后一帧为完整增益；淡出反向变化，最后一帧为零。一帧长的淡入或淡出将该帧静音。重叠区域将两个系数相乘，且各声道保持同步。

WAV 写出 IEEE float32，MP3 将同一 float 数据交给 LAME。编辑器不重采样、不转换声道；有损编码延迟与末尾补帧不属于帧对齐所能消除的误差。

## 取消和进度

`Task.Run` 执行同步解码与编码，工作缓冲按完整声道帧组织，通常最多 4096 个样本。读取、变换和写入之间检查取消，原生调用运行期间不会提前释放其资源。

进度是已处理帧的比例，1 尚未包括编码器收尾和文件发布。同步回调异常会进入失败清理；使用 `Progress<T>` 异步派发时，回调异常由该派发上下文处理。宿主应以方法成功返回作为任务完成点。

## 文件所有权与失败

输入输出的规范化路径必须不同，输出必须不存在。先以 `CreateNew` 创建同目录随机临时文件，完整关闭编码器、输入和输出后，检查取消并用不覆盖目标的移动发布。目标在处理期间被创建也不会覆盖。复制、处理或取消失败只清理本次拥有的临时文件；调用方文件与输入保留。目录须由宿主保证可信且稳定，此 API 不隔离恶意本机文件系统修改，也不检测不同路径的硬链接别名。

强制结束进程或无法删除文件时可能留下临时文件，宿主负责保留期清理。文件已发布后的取消不撤销成功结果。

处理失败时仍释放编码器。处理与编码器收尾同时失败、或处理与临时文件删除同时失败，以 `AggregateException` 保留两者；清理不会替换原来的失败。

## 回归关注点

[AudioEditorTests](../../../test/MS.Microservice.Audio.Tests/AudioEditorTests.cs) 检查实际解码样本、帧数和声道，覆盖时间向下取整、极大增益限幅、重叠／一帧淡变、非有限样本、取消后清理、目标竞争及回调异常。测试样本的读取缓冲同样须按声道对齐，不能用仅适用于单声道或双声道的固定样本数。

Windows 集成用例实际经过 LAME 编码及 NAudio 解码，按编码延迟允许 MP3 时长偏差；它不证明所有平台都具备相同编解码器。
