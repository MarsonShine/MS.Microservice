# 缓存治理的执行边界

HybridCache 已提供本地／共享读取、序列化和同实例并发加载合并。组件只约束键、策略和源加载预算，不实现第二套缓存字典、逐键锁、定时清理器或操作日志存储。

键在创建时对类型名称、Scope、资源标识的长度前缀编码计算 SHA-256，再加入应用与 region。长度前缀防止分隔符拼接碰撞；类型参与身份防止不同 DTO 共用同一键。数据格式版本由 region 明确指定。摘要不是加密或授权，Scope 仍由宿主验证。预建键能避开热命中路径上的摘要和字符串分配。

策略构造时生成不可变的 HybridCacheEntryOptions；同一区域／身份应采用一致策略。绝对过期避免热项无限续期；本地 TTL 不超过共享 TTL。正常值与 null 共享固定 TTL，以一次原生读取保留快速路径；动态负缓存 TTL 需要额外状态或缓存层，本版不引入。原始存量 JSON 的字节协议不复用，新键空间使旧序列化内容无法误命中。

读取先验证键所属应用及取消状态，然后直接调用原生 GetOrCreateAsync。传递值类型 state 与静态委托，避免每次命中新增捕获对象。源工厂真正执行时才尝试领取 SemaphoreSlim 预算；预算耗尽快速拒绝，不无限排队。工厂的成功、异常或取消都在 finally 释放预算。一个请求取消不能由业务闭包误取消其他等待者；加载器应使用框架传入的令牌，并自行持有所需依赖生命周期。

关闭组件或每键绕过时直接调用加载器，不应用缓存预算。写入在绕过状态下不回填；删除仍可清除先前已缓存的内容。无请求正文、完整键、Scope 或资源标识进入指标。指标标签是固定区域名称，宿主仍需控制区域数量。

共享缓存故障时的读写行为沿用原生 HybridCache，组件的源预算限制同时发生的回源。数据库提交与缓存失效没有共同事务。提交前删除可能被旧数据重新填充，因此业务在提交后失效；需要保证通知最终产生时，在数据库事务中写 Outbox，再异步处理失效。广播到每个本地实例需要专门的订阅方式，竞争消费的业务队列不会完成全实例广播。

删除不能阻止已经启动的旧加载回填；共享 L2 删除也不等于其他实例 L1 立即失效。要求严格新鲜的数据应绕过缓存；更严格的版本化协议和广播适配应有独立用例及验证。本版没有宣称强一致或跨实例互斥。宿主负责总缓存容量、业务重试、存储连接和提交结果不确定时的处置。
